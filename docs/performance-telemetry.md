# Performance and usage metrics

Reclinarr can send opt-in, pseudonymous performance and feature usage metrics to the Reclinarr PostHog project in the EU region. The administrator chooses for the whole installation in the setup wizard (on by default); `RECLINARR_TELEMETRY_DISABLED=true` in the environment overrides that choice. When the installation allows it, each user still opts in separately on each device and can change their choice from Profile.

The Reclinarr PostHog project token is built into the API and every client build (`POSTHOG_PROJECT_KEY` in `packages/shared/src/telemetry.ts`). It only permits event ingestion, so it is safe to ship, and there is nothing to configure. The API status endpoint enforces the installation-wide setting for every client.

Every event carries `environment`: `development` for Expo/Metro dev builds (`__DEV__`) and for the API under `npm run dev` or mock mode, `production` otherwise. In PostHog, add `environment = development` to the project's "Filter out internal and test users" setting so insights exclude dev traffic by default.

The app records broad operation names, elapsed time, result category, app version, platform, OS, device type (TV, tablet, mobile, desktop), screen names, a fixed list of feature actions (request, download, My List, live tune/zap/favourite, subtitle and audio language changes, next episode, autoplay), and coarse playback milestones including time watched (rounded to 10 seconds) and rebuffer count when playback ends. Screens are sent as `$screen` on native and `$pageview` (with the screen name as the path) on web. Unhandled web and React Native JavaScript exceptions are also captured when the user has opted into analytics. Exception messages and stack frames have URLs and email addresses removed before sending; exception data can still include other sensitive details embedded in error text or source paths, so avoid putting secrets or personal data in thrown errors. Account identifiers, titles, search text, media IDs, request URLs or parameters, and credentials are not attached. Each opted-in user/device receives a random identifier used to group their events, plus a random session identifier that rotates after 30 minutes of inactivity or 24 hours. The client forwards both to the API so server events join the same session. Client events are sent directly to PostHog in small batches using the public project token; server events are sent by the Reclinarr API. Events disable person profile creation and GeoIP enrichment. Session replay is not enabled.

Instrumentation covers high-cost Reclinarr API routes, provider HTTP calls made during opted-in requests, client API operations, screen views, feature actions, sampled artwork loads, playback source resolution, first playback progress, and playback end. Health checks, auth requests, progress polling, media segments, and stream bytes are excluded. Metrics are best effort and do not affect application operations.
